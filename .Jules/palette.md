## 2026-09-01 - Form Accessibility Patterns
**Learning:** In this application, visual design constraints often prevent explicit visible `<label>` elements for forms (like in RentModal). Relying solely on `placeholder` text is insufficient for accessibility, and adding custom CSS to visually hide a label violates the rule against custom CSS. Additionally, when visible `<label>` elements are present (like in Contact), they are sometimes not explicitly associated with inputs using `htmlFor`/`id`, relying only on structural proximity which is a common but flawed pattern.
**Action:** When working on forms in this app, ensure visible `<label>` elements have explicit `htmlFor` attributes matching their input's `id`. For inputs without visible labels due to design constraints, apply `aria-label` directly to the `<input>` or `<textarea>` element to ensure screen reader accessibility without altering the visual design or adding custom CSS.
